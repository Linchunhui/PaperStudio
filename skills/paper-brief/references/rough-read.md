# 卡片与总结式粗读

## 共同内容

开头共享一份摘要。正文覆盖背景与前作缺口、方法机制、训练/推理或其他流程、主结果、消融/负结果、适用边界。保留能改变读者理解的条件和必要公式，不因样式压缩事实。

方法说明至少回答：输入是什么；核心操作如何变换表示或候选；何处使用监督或反馈；输出是什么；为何这种设计针对前作缺口。训练与推理分别讲，只有一个阶段就不要硬补另一个。机制的关键步骤后给原文页码。

可用小例子走通操作；例子必须标注“解释性示例”，不得伪装论文实验。不得仅列模块名称。公式紧跟变量意义、运算发生了什么、设计意图与限制；变量未定义时回查而非猜测。

保留关键方法总览图和能支持核心比较的图表。每图交代“先看哪里 → 数据/箭头表示什么 → 支持哪条结论”。只有文本输入时标明原图未载入，给图号/页码回看，不宣称已核验图像。

## cards 模式

每张卡只承担一个信息单元：问题/前作、核心机制、训练与推理、关键结果、消融、边界。卡片数量由理解需求决定，不规定屏数。先给结论，再用简短证据或操作说明支撑。避免大量同层级碎片列表。

消融用简短要点，每点保留“变动 → 结果 → 条件”。不做多列表格，不逐条附泛化迁移建议。把有条件的启发留到边界或最终少量判断中。

## summary 模式

用连续讲解恢复作者解决问题的逻辑：前作瓶颈引出设计动机，设计动机引出机制，实验验证机制能否兑现。段落衔接回答“为什么接着需要这一步”。不要把卡片的标题和要点机械串成段落。

主结果解释对照、公平性、代价和实证范围。消融可使用紧凑表格：改动、结果、支持判断、借鉴条件。缺少消融时说明实际证据类型。

## all 模式

摘要只出现一次；卡片与总结复用相同版本和证据。可在总结中展开卡片略去的解释，不改变数字、条件或结论强度。出现矛盾先修正再交付。

## 最终检查

尝试不看论文复述方法，若只能说出模块名而不能说出操作就继续补机制。核对结果与消融是否混淆；负结果与成本是否保留；来源页码是否实际存在；局部材料是否被不当扩大为全文结论。
