# 摘要规范

写一个可独立阅读的紧凑中文摘要，优先用一段或少量连贯段落，不把 Abstract 逐句翻译当作任务完成。

按理解顺序交代：

1. 问题发生在什么具体背景，实际痛点是什么。
2. 前人主流路线如何解决，在哪个关键环节仍受限。
3. 本文从哪里切入，核心操作怎样把输入变为输出。
4. 在什么设置中得到什么主要结果，结论的适用边界是什么。

比例服从论文类型；方法论文多解释机制，数据论文交代采集/标注/覆盖及验证，基准论文交代任务构造/协议/度量及发现，综述交代范围/分类依据/实证程度。不要为了模板编出不存在的训练过程或消融。

选择性加粗痛点、关键操作和主要结果，避免只加粗术语。首次出现的重要术语保留原文名，之后采用一致译名。优先解释行为，再给模块名。

摘要不堆基准、不罗列全部消融、不设悬念、不承诺“全面解决”。若结果证据不足，直接说明已知与未知。末尾提供能定位核心方法与结果的少量页码引用。

若用户给出字数限制，遵守并实际计数；否则不设机械上限。压缩到论证链闭合即可，不以短到无法复述方法为目标。
